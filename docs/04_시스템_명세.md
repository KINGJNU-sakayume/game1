# 04. 시스템 명세

> 상태: **확정** — 14일 대본과 새 앱(튜브·지도·스냅·망원살이) 기준. 수치는 `npm run playtest`로 조정한다.
> 루트 진입 기준치와 엔딩 조건은 `03_분기_지도.md`.

## 1. 변수

모든 게임 변수는 ink 변수로 둔다. 정의 파일: `story/system.ink`. 엔진(`src/engine/director.ts`)은 대사 한 줄과 선택 한 번이 끝날 때마다 이 변수를 읽어 화면에 반영한다.

| ink 변수 | 범위 | 기본값 | 설명 |
|---|---|---|---|
| `player_name` | 문자열 | "도현" | 주인공 이름. 설정 앱에서 바꾸면 엔진이 덮어쓴다 |
| `aff_seoha` · `aff_ian` · `aff_daon` | 0~100 | 0 | 히로인별 호감. **화면에 숫자로 보이지 않는다** |
| `skill` | 0~3 | 0 | 수리 실력. 튜브 영상을 볼 때마다 +1 (연애 상담 영상 `timing`은 제외) |
| `k_…` | true/false | false | **수리 지식.** 영상마다 하나(`k_boiler`, `k_breaker`, `k_roaster` …). `story/videos.ink`의 영상 터널이 켠다 |
| `roaster_step` | 0~3 | 0 | 서하 루트의 로스터 수리 진척 (영상 ①·②, 사장님 조언마다 +1. 2 이상이면 성공) |
| `f_book_read` | true/false | false | 밤에 사장님 수첩을 통째로 읽었다 (`read()`가 모두 참인 것과 같은 효과) |
| 플래그 (자유) | true/false | false | `VAR f_seoha_honest = false`처럼 `f_`로 시작. 날짜별 파일 맨 위에 선언한다. 엔진은 읽지 않는다 |
| 루트 변수 | 숫자 | 0 | `d4_pick`, `d5_with`, `menu_name`, `daon_regular`처럼 플래그로 부족한 것 |

### 엔진이 대답하는 함수 (EXTERNAL)

| 함수 | 대답 | 예 |
|---|---|---|
| `saved("사진")` | 플레이어가 그 사진을 사진첩에 **저장**했는지 | `{saved("ian_cg_doodle_light_01"): 저장했네요?}` |
| `read("쪽 제목")` | 플레이어가 메모 앱에서 사장님 수첩의 그 쪽을 **열어 봤는지** | `{k_breaker \|\| read("오후세시 (에스프레소 머신)"): …}` |

플레이어가 앱에서 한 일을 대본이 나중에 확인하는 통로다. 사진을 저장해 두거나 수첩을 미리 읽어 둔 플레이어가 보상을 받는다.

### 대본에서 바꾸는 법

```ink
~ raise(aff_seoha, 5)     // 호감 +5 (0~100을 넘지 않음)
~ raise(aff_ian, -3)      // 호감 -3
~ study()                 // 수리 실력 +1 (최대 3)
~ f_seoha_honest = true   // 플래그
{aff_daon >= 50: 밥은.|그 번호 왜 쓰세요.}   // 조건에 따라 다른 대사
```

## 2. 호감 단계

| 단계 | 호감 | |
|---|---|---|
| 1 | 0~24 | 첫 만남 |
| 2 | 25~49 | 호의 |
| 3 | 50~74 | 관심 |
| 4 | 75~ | 설렘 |

### 호감 변화량 가이드

| 행동 | 변화 |
|---|---|
| 작은 호의 (정중한 답장, 약속 지키기) | +3 ~ +5 |
| 그 인물이 **가장 중요하게 보는 행동** (서하: 솔직함 / 이안: 새벽 연락에 답하기, 구체적인 감상 / 다온: 정직함, 시간 약속) | +8 ~ +15 |
| 싫어하는 행동 (허세, 대충 칭찬, 지각 등) | −5 ~ −10 |

D5 밤 루트 결정까지 한 히로인에게 집중하면 3단계 후반(65~70), 모두에게 고루 친절하면 2단계(35~45)에 닿는다. 루트 기준치는 35(`03_분기_지도.md` 3장), 굿 엔딩은 4단계(75)가 필요하다. 호감은 100을 넘지 않으므로, 루트 후반의 결정적인 선택은 호감이 아니라 **플래그**로 판정한다.

## 3. 호감 신호 (숫자 대신 보이는 것)

단계가 바뀌면 다음 메시지부터 바로 반영된다. 값은 `02_캐릭터_바이블.md`에서 가져왔고 `src/story/cast.ts`의 `STAGE_SIGNALS` · `READ_DELAY`에 있다.

| 신호 | 어디에 보이나 |
|---|---|
| 프로필 사진 | 대화 목록, 말풍선 옆 아바타, 프로필 보기(아바타를 누르면 열림) |
| 상태 메시지 | 1:1 대화방 헤더의 이름 아래, 프로필 보기 |
| 답장 속도 | 주인공 메시지 옆의 **"1"(안 읽음)** 이 사라질 때까지 걸리는 시간 |
| 말투 | 대본 담당 — `{aff_seoha >= 25: …|…}` 조건문으로 단계별 대사를 쓴다 |

### 읽음 시간 (초, 텍스트 속도 설정이 곱해짐)

| | 1단계 | 2단계 | 3단계 | 4단계 |
|---|---|---|---|---|
| 서하 | 5 | 3.5 | 2 | 1 |
| 이안 | 1.2 | 0.8 | 0.5 | 0.3 |
| 다온 | 7 | 5 | 3 | 1.5 |
| 그 외 | 1.5 | | | |

- 1:1 방에서 주인공이 메시지를 보낸 뒤 **상대의 다음 대사**가 나오기 전에 이 시간만큼 기다리고 "1"을 지운다. 그다음 입력 중 표시가 나온다.
- 그 대사에 `# wait:`가 있으면 그 시간을 읽는 시간으로 쓴다 (예: 이안 마감 주간엔 `# wait: 20`).
- 단톡방에는 읽음 표시가 없다.

## 3-1. 수리 지식 — 튜브와 수첩

수리 장면은 **플레이어가 미리 배웠는지**로 선택지가 바뀐다.

| 배우는 곳 | 어떻게 | 대본에서 |
|---|---|---|
| 튜브 | 밤의 할 일 → 튜브에서 영상 고르기(`# watch:`) → 재생 화면 → 핵심 정리 | `k_…` 가 켜진다 |
| 사장님 수첩 | 메모 앱 → 사장님 수첩 → 그 쪽을 연다 (D3부터) | `read("쪽 제목")` 이 참 |

- 영상 목록과 핵심 정리: `src/story/videos.ts`. 영상 대사(오반장의 설명): `story/videos.ink`.
- 수리 장면에는 보통 세 갈래가 있다: **배운 대로 하기**(지식이 있을 때만) / 아는 척 도전하기 / 솔직하게 못 한다고 하기.
- 영상 16편: 형광등 점등관, 냉장고 문 고무, 보일러 공기 빼기, 경첩 핀, 그라인더, 의자 실린더, 줄 전구 퓨즈, 차단기, 로스터 ①·②, 도어락 9V, 물병 랜턴, 보온기, 녹슨 볼트, 제주 만물수선(사장님), 연애 상담(수리 아님).

## 3-2. 기록 (journal)

엔진은 대본의 태그와 플레이어의 앱 사용을 **기록**으로 쌓는다. 기록은 저장본에 함께 들어가고, 날짜 선택으로 되돌리면 그 날짜의 기록으로 돌아간다.

| 기록 | 쌓는 것 | 보이는 앱 |
|---|---|---|
| `photos` | 저장한 받은 사진, `# gallery:` 사진 | 사진 |
| `plans` · `events` | `# plan:` 약속(취소 표시 포함), `# event:` 행사 | 캘린더 |
| `notes` · `todos` | `# note:` 속마음, `# page:` 수첩, 보내지 못한 말, `# todo:` | 메모 |
| `readPages` | 플레이어가 연 수첩 쪽 | 메모 (안 읽은 쪽에 점) → `read()` |
| `videos` | 본 영상과 시각 | 튜브 보관함 |
| `visits` · `pins` · `location` | `# at:` 다녀온 곳, `# pin:` 드러난 장소, 지금 있는 곳 | 지도 |
| `posts` | `# post:` 스냅 게시물, `# comment:` 댓글, 좋아요, `# unpost:` 삭제 | 스냅 |
| `town` | `# town:` 동네 글, `# townreply:` 답글, 내 답글 | 망원살이 |
| `memos` | `# memo:` 인물 메모 (연락처에서 보는 "알게 된 것") | 전화 → 연락처 |
| `voicemails` | `# voicemail:` 음성 메시지 (들었는지) | 전화 → 음성사서함 |
| `history` | 그날의 선택 (고른 것과 고르지 않은 것) | 하루 결산 흐름도 |

통화 기록(`calls`: 받은/건/거절/부재중/연결 안 됨, 모르는 번호 여부)은 기록과 따로 저장본에 들어간다.

### 알림과 배지

| 앱 | 배지 숫자 | 알림 배너 |
|---|---|---|
| 메신저 | 안 읽은 메시지 | 다른 방에 온 메시지 |
| 전화 | 확인 안 한 부재중 + 안 들은 음성 메시지 | 부재중 전화, 새 음성 메시지 |
| 스냅 | 안 본 게시물 | 새 게시물 |
| 망원살이 | 안 본 동네 글 | 새 동네 글 |

- 그 앱을 **열고 있는 동안** 온 소식은 배너를 띄우지 않고 바로 본 것으로 한다.
- 선택을 기다리는 앱 아이콘에는 배지 대신 **점**이 붙고, 홈 화면과 다른 앱 헤더 아래에 **알약**이 뜬다 (`06_UI_연출_명세.md`).

## 4. 게임 시각

- 날짜: `# day: N` (D1 = 3월 9일 월요일 … D14 = 3월 22일 일요일). 엔딩 에필로그는 D14 뒤로도 간다(예: `# day: 42` = 4월 19일). 요일은 실제 달력으로 계산한다.
- 날씨: `src/story/weather.ts` (D3·D8·D11 흐림, D6 구름 조금, D9 비, D10 갬, 나머지 맑음). 홈 위젯과 캘린더에 나온다. 대본의 날씨 묘사와 맞춘다.
- 시각: `# time: HH:MM` — 실시간이 아니라 대본이 정한다. 메시지 시각, 잠금화면 시계, 홈 위젯에 쓰인다.
- 하루 네 구간(아침·낮·저녁·밤)은 시각으로 표현한다. 구간별 규칙은 `03_분기_지도.md`에서 정한다.

## 5. 저장

플레이어가 직접 저장하지 않는다. 모두 자동이다. localStorage `jgbn_` 접두사.

| 키 | 언제 | 내용 |
|---|---|---|
| `jgbn_resume` | **대사 한 줄이 끝날 때마다**, 선택지가 나올 때 | 이어하기 지점 1개. 앱을 다시 열면 여기서 이어진다 |
| `jgbn_days` | 날짜가 바뀔 때(`# day:` 줄을 처리한 직후) | 날짜별 시작 지점. 설정 앱 **날짜 선택**에 쓴다 |
| `jgbn_log` | resume과 함께 | 메시지 기록. 저장본마다 메시지 개수만 기억해 앞부분을 공유한다 |
| `jgbn_seen` | 선택할 때마다 | 지금까지 한 번이라도 고른 선택 (흐름도의 "다른 회차에 고른 선택"). 날짜 선택으로 되돌려도 남는다 |
| `jgbn_endings` | 엔딩 카드가 뜰 때 | 본 엔딩 id 목록 (설정 앱 "엔딩 기록") |
| `jgbn_profile` · `jgbn_settings` | 설정할 때 | 이름, 텍스트 속도 |

- 각 저장본: **세이브 버전**, ink 진행 상태(`story.state.ToJson()`), 게임 시각, 안 읽음 수, 현재 방, 메시지 개수, 무대(대면·통화 중이었다면), 통화 기록, 기록(journal).
- **세이브 버전 2**: 새 앱이 생기며 저장 구조와 대본이 크게 바뀌었다. 버전이 다른 저장본은 불러오지 않고 처음부터 시작한다 (`src/engine/save.ts`의 `SAVE_VERSION`). 저장 구조나 대본의 knot 구조를 크게 바꾸면 이 숫자를 올린다.
- 기획서는 "하루 결산 시 자동 저장 1개"였지만, 폰 게임 특성상 앱을 닫는 일이 잦아 **줄마다 이어하기 저장**을 추가했다. 하루 결산(M5) 직후는 다음 날 시작 지점이 되므로 기획 의도와 같다. 입력 중 표시·대면 대사처럼 한 줄이 끝나기 전에 앱을 닫으면 그 줄부터 다시 나온다.
- **날짜 선택**: 고른 날짜 시작 지점을 이어하기로 만들고, 그 뒤 날짜 저장본은 지운다(다른 갈래가 되므로).
- **데이터 초기화**: `jgbn_`로 시작하는 키를 모두 지운다 (엔딩 기록 포함).
- 대본이 크게 바뀌어 저장본을 불러오지 못하면 처음부터 시작한다(개발 중 주의).
